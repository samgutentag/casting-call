1. What this is

casting-call is a set of command-line tools that run after a call is recorded. You record the call with OBS as one .mkv that holds the screen plus separate audio tracks, and casting-call turns that file into a timestamped, speaker-labeled transcript. The whole thing runs locally: no accounts, no uploads.

It is for one person (you) processing your own recorded calls, comfortable in a terminal. It does not record the call, join the meeting, or run in real time, and it does not guess at a speaker it cannot confidently identify. Anything uncertain stays labeled Caller rather than being made up.

The map: ripa transcribes, rips puts real names on the far-side lines, ripcap rebuilds the far side from on-screen captions when its audio failed, and ripv renders a playable video. Setting up the recording rig itself is a separate document, docs/setup-guide.html.

2. Install and prerequisites

The tools lean on ffmpeg and Whisper for audio and tesseract for reading captions. On a fresh Mac:

brew install ffmpeg whisper-cpp tesseract
pip3 install --break-system-packages pillow numpy pytesseract

# Whisper model, ~3 GB, one time
mkdir -p ~/whisper-models
curl -o ~/whisper-models/ggml-large-v3.bin -L \
  'https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3.bin?download=true'

# Your roster of names (stays local, gitignored)
cp speakers_roster.example.json speakers_roster.json   # then edit it
The short command names (ripa, rips, and the rest) are shell aliases that live in a separate dotfiles repo, not here. Every command also works without them: run bash bin/<script>.sh ... from the repo root. This guide shows both.
The transcriber expects the Whisper model at ~/whisper-models/ggml-large-v3.bin. If it is missing, ripa stops and prints the exact download command rather than guessing.

3. Words you need first

Track
One audio stream inside the recording. The rig records three: Track 1 (0:a:0) is your mic, Track 2 (0:a:1) is the far side, Track 3 (0:a:2) carries marker sounds only. The tools read tracks by number, not by channel-splitting a stereo mix.
You / Caller
The two speaker labels in a fresh transcript. You is your mic (Track 1). Caller is everyone on the far side (Track 2), lumped together until rips puts real names on them.
Marker
A moment you flagged during the call by pressing a Stream Deck button, which played a short "mark flag / action / question / important / quote" sound onto Track 3. In the transcript it becomes a [MARKER] line at that timestamp. The label is MARKER, not MARK, so it never collides with a real person named Mark.
Transcript
A plain-text file of [h:mm:ss] [Label] text lines, sorted by time. Everything downstream reads and writes this one format.
Dropout
When a track captures fine and then goes silent mid-call (the far-side capture is prone to this). The transcriber flags a sustained silence and points you at recovery.
Hallucination
Words Whisper invents when it transcribes silence, like a repeated "Thank you" or "Subtitles by the Amara.org community." casting-call strips these automatically wherever a track was silent.
Caption region
The x,y,w,h rectangle, in full-frame pixels, where Meet draws its on-screen captions. rips and ripcap read that rectangle, so they need it as --region.
Roster
Your local speakers_roster.json: your own name plus the people you call. Caption OCR fuzzy-matches against it, so a noisy read still lands on the right name.

4. Transcribe a call ripa

Point it at a folder holding one or more recordings. It reads each .mkv directly, no conversion step.

ripa ~/calls/2026-07-24
# or, without the alias:
bash bin/extract_audio_stereo.sh ~/calls/2026-07-24

For each recording it pulls Track 1 and Track 2 out as mono audio, checks each for silence, transcribes the ones that have speech, and weaves them into transcripts/<name>.txt. Then it reads Track 3 and folds your markers in at their timestamps. A recording that already has a transcript is skipped, so re-running the folder is safe and cheap.

If the far-side track went silent for a long stretch, ripa warns that the capture likely dropped and tells you the timestamp, then points you at ripcap. The transcript is still produced from whatever real audio exists.

5. Commands and flags

CommandScriptWhat it does
ripa [dir]extract_audio_stereo.shTranscribe every recording in a folder to transcripts/, markers folded in.
ript [root]transcribe_batch_stereo.shTranscribe across dated subfolders (<root>/<date>/converted_video/*.mp4).
ripv [dir]convert_video.shOptional: render a playable .mp4, you on the left channel, caller on the right.
rips rec --region ...extract_speakers.shOCR the captions, put real names on Caller lines.
ripcap rec --region ...stitch_captions.shRebuild the far-side words from captions when its audio failed.

ripa, ript, and ripv take a directory (default: current) and, for the transcribers, an optional Whisper model path as a second argument. The two caption tools take the recording plus the flags below.

6. Put names on speakers rips

A fresh transcript calls everyone on the far side Caller. Meet's on-screen captions already say who is speaking, so rips samples the video, OCRs the caption band, matches names against your roster, and rewrites the Caller lines with real names. Names it cannot place stay Caller, and it asks you about the ones it is unsure of.

rips recording.mkv --region 120,1850,900,180 --transcript transcripts/recording.txt
# or:
bash bin/extract_speakers.sh recording.mkv --region 120,1850,900,180 --transcript transcripts/recording.txt
FlagDefaultWhat it does
--region x,y,w,hrequiredCaption crop in full-frame pixels. Without it the tool stops.
--transcriptnoneAn existing transcript to relabel in place.
--callers Nauto1 forces "one other person" (all Caller lines become them); 2 or more forces timed attribution. Omit to auto-detect.
--rosterspeakers_roster.jsonWhere to read names from.
--outnext to the recordingOutput directory for frames and speakers.json.

7. Recover a dead channel ripcap

When the far-side audio never made it to disk, the words are still on screen as captions. ripcap OCRs every caption frame and stitches the rolling text into one attributed transcript. This is the tool ripa points you at when it warns about a dropout.

ripcap recording.mkv --region 120,1850,900,180
# or:
bash bin/stitch_captions.sh recording.mkv --region 120,1850,900,180
FlagDefaultWhat it does
--region x,y,w,hrequiredCaption crop. Required unless the input is a folder of pre-cropped frames.
--fps1.5How often to sample caption frames. Captions scroll slowly, so this is low on purpose.
--jobs8Parallel OCR workers.
--rosterspeakers_roster.jsonNames for attribution.
--outtranscripts/ next to the recordingWhere the stitched transcript lands.
The caption region is fixed for the whole run, so the Meet window has to stay in one place and size during the call. If it moved or resized, a single region will not cover the recording, and you have to recover one layout at a time.

8. Render video and batch ripv ript

ripv is optional and only for when you want to watch a call back. It rebuilds the audio into one stereo track, you on the left channel and the caller on the right, copies the video without re-encoding, and writes a .mp4 to converted_video/. The pipeline never needs it; it reads the .mkv.

ripv ~/calls/2026-07-24     # -> converted_video/*.mp4, you=left / caller=right

ript is ripa for many folders at once: point it at a parent directory and it transcribes every converted_video/*.mp4 under each dated subfolder.

9. Good to know

How do I run these without the aliases?
Every command maps to a script in bin/. Run bash bin/<script>.sh ... from the repo root. The mapping is in the commands table above.
What does it write to disk?
ripa writes transcripts/. ripv writes converted_video/. rips writes frames/ and speakers.json and edits the transcript in place. ripcap writes a stitched transcript. Your original recording is never modified.
Is it safe to re-run?
Yes. ripa skips any recording that already has a transcript, so re-running a folder only picks up new files. Delete a transcript if you want it rebuilt.
Why is there a repeated "Thank you" or "Amara.org" line in an old transcript?
Those are Whisper hallucinating on silence. The current pipeline strips them automatically inside any silent span, so fresh transcripts should be clean. If you see them, the audio there was dead, which is a hint to check for a dropout.
Do I have to say the marker names out loud?
No. You press the Stream Deck button silently; the sound goes onto Track 3, which the far side never hears. Only the [MARKER] line appears in the transcript.
Does anything leave my machine?
No. Whisper and tesseract run locally. There are no accounts and no uploads.
