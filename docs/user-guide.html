casting-call: User Guide

Turn a recorded call into a review page: what you were asked to do, what is owed to you, who said what, and the moments you flagged. Written to be read cold, with no prior knowledge of the tool assumed.

1. What this is

casting-call is a set of command-line tools and one Claude Code skill that run after a call is recorded. OBS records the call as one .mkv with the screen plus separate audio tracks, fed by a Zoom PodTrak P4next. The P4next also writes every channel to its own microSD card as a backup. casting-call turns those into a transcript with real names on the far side, a screen grab for every moment you flagged, and a review page that leads with your to-do list.

It is for one person processing their own calls, comfortable in a terminal. It does not join the meeting or run in real time. The goal is the fastest path from a finished call to the review page. The one manual step, choosing which calls to file, is there on purpose: it keeps calls you do not care about out of the pipeline.

2. Call to report, start to finish

  1. Before the call: P4next on, OBS on the Call P4 scene, Meet captions (CC) on. Start OBS recording, press REC on the P4next, then press pad A once. That first press lines the card up with the video later.
  2. During: press pad A whenever a moment is worth coming back to. Mute in Meet, not on the P4next.
  3. After: stop both recorders. On the P4next, Menu > USB File Transfer, run ripcard, and exit File Transfer as soon as it says so.
  4. File it: for a call worth keeping, move the .mkv and its card take into call_logs/<week>/<date>/ and give them one name.
  5. Transcribe: ripa on the day folder.
  6. Review: /process-transcript on the call folder, in Claude Code. The report opens in Chrome.

The rig itself (wiring, P4next menu settings, the OBS scene) is in docs/setup-guide.html and on the call rig page in docs/call-rig/.

pip3 install --break-system-packages pillow numpy pytesseract
# optional, for the styled output
brew install gum

# Deepgram key, in the repo root (gitignored)
echo 'DEEPGRAM_API_KEY=...' >> ~/Developer/casting-call/.env
# whisper model, only used as the fallback (~3 GB, one time)
mkdir -p ~/whisper-models
curl -o ~/whisper-models/ggml-large-v3.bin -L \
  'https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3.bin?download=true'
# the report skill, linked once per machine
ln -sfn ~/Developer/casting-call/skills/process-transcript ~/.claude/skills/process-transcript
The short command names (ripa, ripcard, and the rest) are shell aliases that live in a separate dotfiles repo, not here. Every command also works without them: run bash bin/<script>.sh from the repo root. The mapping is in the commands table below.

4. Words you need first

Track
One audio stream inside the OBS recording. Track 1 is the mix (your mic plus computer audio, mixed in OBS). Track 2 is your mic (P4next channel 1). Track 3 is computer audio, which is the far side of the call (channels 7-8). Track 4 is the marker (the sound pads, channels 9-10). Older recordings had three tracks and no mix; ripa reads both.
You / the far side
You is your mic. Every other label is the far side: Caller when no name was found, or a real name read from Meet's captions, like Corey Weathers.
Second voice
A second voice that came through one person's Meet connection, such as a voice demo they ran or a second person in their room. It shows as Ed Charbeneau (second voice).
Marker
A moment you flagged by pressing pad A on the P4next. It plays the word "marker" onto Track 4 and the card's pads file. Nobody on the call hears it. In the transcript it is [0:12:34] [MARKER] marker, and ripa saves a full-resolution screen grab for it. The P4next's PLAY key adds a silent mark to the card, which becomes a marker the same way.
Card take
The P4next's own recording of one call: a stereo mix plus one file per channel (_MIC1, _USB, _SOUND_PAD). It is the backup for anything OBS dropped.
Transcript
A plain-text file of [h:mm:ss] [Label] text lines, sorted by time, with a few # header lines saying which engine transcribed each track. Everything downstream reads this one format.
Dropout
A track that records fine and then goes silent mid-call. With a card take, ripa fills the gap from the card. Without one, a Meet call's far side is filled from the on-screen captions.

5. Pull the card ripcard

While the P4next is in USB File Transfer mode it is not the Mac's audio device, so you hear no computer audio. ripcard keeps that window short: it copies only takes it has not pulled before into ~/Desktop/P4next-takes/, ejects the card, and prints Card ejected. Exit USB File Transfer on the P4next now.

ripcard        # run from any folder
  • Progress: one line with percent, MB, speed, time left and the current file. A one-hour call is about 3.7 GB, a few minutes over the P4next's USB.
  • Never twice: every pulled take is listed in ~/Desktop/P4next-takes/.pulled, so a take you moved into call_logs or deleted is not copied again. PULL_AGAIN=1 ripcard ignores that list.
  • Skipped on purpose: MIC2 to MIC4 are unused inputs and pure silence. PULL_ALL_INPUTS=1 copies them anyway.
  • Safe: nothing on the card is changed or deleted. Clear the card from the P4next menu now and then. If a copy fails, the card stays mounted and you rerun.

6. File the call

This step is manual on purpose: only calls worth keeping go in. Put the recording and its card take loose in the day folder, with one shared name. ripa creates the call's own folder next to them.

call_logs/2026-w47/2026-11-16/
  2026-11-16-devrel-weekly.mkv        <- from ~/Desktop, renamed
  2026-11-16-devrel-weekly.card/      <- from ~/Desktop/P4next-takes/261116_125935/, renamed
  2026-11-16-devrel-weekly/           <- ripa writes this

Renaming the take is optional: an unrenamed take folder in the day folder is paired with its recording by start time, and ripa says which one it picked. It refuses a pairing more than 10 minutes apart.

7. Transcribe a call ripa

ripa ~/Desktop/call_logs/2026-w47/2026-11-16
# or, without the alias:
bash bin/extract_audio_stereo.sh ~/Desktop/call_logs/2026-w47/2026-11-16

For each recording without a transcript, ripa runs six steps and prints them as [1 of 6] to [6 of 6]:

  1. Extract tracks from the .mkv. Reading Meet's caption frames starts at the same time, in the background, cached to parts/caption-frames.json.
  2. Card take: line it up with the video from the pad presses (written to align.json), then fill any OBS dropout from the matching card file.
  3. Transcribe both tracks with Deepgram nova-3 at the same time. Your track is plain; the far side is diarized, so Deepgram splits it into speakers. If a request fails, that track falls back to whisper on this Mac, with a loud warning line.
  4. Caption backup: on a Meet call, a long far-side silence with no card to fill it gets its words from the on-screen captions.
  5. Caption names: each Deepgram speaker gets the Meet caption name its words belong to (details below).
  6. Markers and frames: each pad press and PLAY mark becomes a [MARKER] marker line and a full-resolution PNG in markers/.

It ends with a table of step times, the total, and a ready for review line with the exact /process-transcript command to run next. With gum and rich installed the output is styled; RIPA_PLAIN=1 or a missing tool gives plain text. Statuses always say ok, warn or failed in words.

How far-side names are found

Meet labels every caption with the speaker's display name, so turn captions on for every call. ripa reads a frame every 2 seconds, finds the caption panel from Meet's red end-call button (so the window can move), and collects the names. There is no roster: names come from the captions alone.

  • Misreads are folded into the most common spelling ("Corey", "Corey Weathore" and "Corey Weathers" are one person). A name seen in only one frame is dropped, and "You" (Meet's label for you, including OCR misreads like "vou") never counts.
  • Caption words are shifted 2.5 seconds earlier, because captions trail the voice.
  • A Deepgram speaker takes a name when that name holds at least 60% of its caption words, with a lead of at least 3 times the runner-up, over at least 20 words. Otherwise it stays Caller.
  • If two speakers win the same name, the one who talked more keeps it and the other becomes <Name> (second voice).
  • On a call with only one far-side person, every far-side line gets that name.

The unnamed transcript is kept in parts/pre-names.txt, and every speaker's votes are in parts/speaker-names.json. A whisper transcript has no speakers, so there each line is voted on alone (70% of at least 5 caption words).

Transcription sends each track to Deepgram. Every request carries mip_opt_out=true, which keeps the call audio out of Deepgram's Model Improvement Program, and it cannot be turned off. TRANSCRIBER=whisper ripa ... keeps the whole run on this Mac.

What it writes

name/
  name.txt                  the merged transcript
  name.mp3                  the whole call, for the report's audio player
  markers/marker-HHMMSS.png one full-resolution frame per marker
  markers.json              each marker's time, type and frame
  align.json                card offset and how it was found
  parts/                    per-track audio and transcripts, Deepgram responses,
                            caption-frames.json, speaker-names.json, pre-names.txt,
                            health.txt (OBS against the card, per track)

8. Review the call /process-transcript

In Claude Code, from any folder:

/process-transcript ~/Desktop/call_logs/2026-w47/2026-11-16/2026-11-16-devrel-weekly

It writes <name>-call.html next to the transcript and opens it in Chrome. Give it a day folder and it also writes a day page; a parent folder adds an index.

Always visible, in this order:

  1. Stat tiles (length, people, asks, owed, marked) and a play bar that stays at the top.
  2. Asks of you: "Corey Weathers asked you to ..." or "You said you'd ...", each with a ▶ button that plays from that moment.
  3. Owed to you: "Greg will ...".
  4. Summary and Decisions.
  5. Marked moments: each pad press with a one-line summary of the talk around it and its screen grab.

Behind Show more: open questions, the call cut into subject sections, Who's speaking (one labeled row per person, talk share, how the names were found), and Transcript by speaker (one column per person, four on screen, scroll sideways for more). Rows and columns carry each person's name, so nothing relies on color.

Lines the model found, rather than ones you flagged, carry an inferred badge so you can prune them. A machine-readable <name>-summary.json (people, asks, owed, decisions, subjects, markers) is written next to the page for cross-call logs later.

10. Other tools

ripv renders a small H.265 .mp4 of a call to watch back, about 40 times smaller than the .mkv. ripcap rebuilds a whole far side from captions given a fixed --region x,y,w,h; ripa's automatic caption backup does not need a region. rips is the older naming tool that matches captions against a roster file; it stays for old recordings but is no longer needed.

Recordings from before 2026-11-14 used seven Stream Deck keys for markers (topic, action-me and so on). ripa still reads those, and the report still renders them.

11. Good to know

Is it safe to rerun?
Yes. ripa skips any recording that already has a transcript, so rerunning a folder only picks up new files. Delete a transcript to rebuild it.
Why are some far-side lines still "Caller"?
No name won clearly: captions were off, Meet was not on screen, or people overlapped. parts/speaker-names.json shows the votes.
Who is "(second voice)"?
A second voice on one person's connection, often a voice demo they played. On the 2026-11-16 weekly it was Ed's game, which Deepgram split out from Ed.
Do people on the call hear the marker?
No. Pad A plays on the P4next's pads channel, which goes to OBS Track 4 and the card, never to Meet.
Does anything leave my machine?
Each track's audio goes to Deepgram for transcription, with mip_opt_out=true on every request. Caption reading, naming, frames and the report all run locally. TRANSCRIBER=whisper keeps transcription local too.
How long does it take?
Transcription takes seconds. For an hour of 4K call, extracting tracks and reading captions take a few minutes each, and they run at the same time.
